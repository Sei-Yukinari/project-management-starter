## 書き方ガイド

1. **プロジェクト概要**から着手し、「何を作るか」の前に目的と成功基準について顧客との共通認識を固めます
2. **要求定義**では顧客の要望をそのまま要求にせず、背景にある目的を確認したうえで「実現したいこと」として整理し、REQ-xxx の ID を採番します(要望は顧客の言葉のままヒアリングメモに残します)
3. **要件定義**では要求を実装・評価できる水準のシステム要件へ具体化し、各要件に対応する要求 ID と検証方法を必ず記載します(トレーサビリティ)
4. 合意後の変更は、プロジェクト概要の**変更管理**に従って影響分析を行い、要求定義の変更履歴に理由とともに記録します

用語の区別(要望・要求・要件)と要件文の書き方は、IPA「AI時代の要求管理ハンドブック」の整理に沿っています。
